# Thinkollect Custom API Contract

This document specifies the complete API contract between the mobile app and the custom FastAPI backend. 
Since the app no longer uses the Supabase client directly, all Auth and Data Sync logic is routed through this backend. Auth is custom (backend-signed JWTs); Supabase is used as Postgres + pgvector only.

## Global Specifications
- **Base URL:** `http://localhost:8000/api`
- **Authentication:** Standard JWT Bearer token required in headers for protected routes.
  - `Authorization: Bearer <token>`
- **Content-Type:** `application/json`

---

## Part 1: Authentication API

### 1.1 Sign Up
Registers a new user against the backend's own `users` table (argon2 password hash + JWT). Password minimum: 8 characters.

**Request:** `POST /auth/signup`
**Body:**
```json
{
  "email": "user@example.com",
  "password": "securepassword123"
}
```
**Response: `201 Created`**
```json
{
  "status": "success",
  "user": {
    "id": "uuid-string",
    "email": "user@example.com"
  },
  "token": "jwt-access-token-string"
}
```

### 1.2 Login
Authenticates an existing user and returns a session token.

**Request:** `POST /auth/login`
**Body:**
```json
{
  "email": "user@example.com",
  "password": "securepassword123"
}
```
**Response: `200 OK`**
```json
{
  "status": "success",
  "user": {
    "id": "uuid-string",
    "email": "user@example.com"
  },
  "token": "jwt-access-token-string"
}
```

### 1.3 Get Current User Profile (Protected)
Validates the current token and fetches user info.

**Request:** `GET /auth/me`
**Headers:** `Authorization: Bearer <token>`

**Response: `200 OK`**
```json
{
  "id": "uuid-string",
  "email": "user@example.com",
  "created_at": "2024-01-01T12:00:00Z"
}
```

## Part 2: Data Sync API (Protected)
All routes below require the `Authorization: Bearer <token>` header.

### 2.1 PULL: Fetch Remote Changes (Sync Down)
Fetches thoughts created or modified on other devices since the last sync.

**Request:** `GET /thoughts/sync`
**Query Parameters:**
- `last_sync` *(optional, string)*: ISO-8601 timestamp. If provided, return thoughts where `updated_at > last_sync`. If omitted, return all thoughts for the user.

**Response: `200 OK`**
```json
[
  {
    "id": "uuid-string",
    "content": "This is a thought synced from another device",
    "tags": ["idea", "work"],
    "captured_at": "2024-01-01T12:00:00Z",
    "updated_at": "2024-01-01T12:05:00Z",
    "deleted_at": null
  },
  {
    "id": "uuid-string-2",
    "content": "This thought was deleted",
    "tags": [],
    "captured_at": "2024-01-01T10:00:00Z",
    "updated_at": "2024-01-02T08:00:00Z",
    "deleted_at": "2024-01-02T08:00:00Z",
    "insight": null
  }
]
```

`insight` is a mentor-style comment generated by the backend after a thought is pushed. It may be `null` until generation succeeds.

### 2.2 PUSH: Send Local Changes (Sync Up)
Sends bulk inserts, updates, and soft-deletes from the device's local database to the server. The server will also generate embeddings for these new/updated thoughts during this step.

**Request:** `POST /thoughts/sync`
**Body:**
```json
{
  "thoughts": [
    {
      "id": "uuid-string",
      "client_id": "unique-device-identifier",
      "content": "My new thought content",
      "tags": ["personal"],
      "captured_at": "2024-01-03T14:20:00Z",
      "updated_at": "2024-01-03T14:20:00Z",
      "deleted_at": null
    }
  ]
}
```

**Response: `200 OK`**
```json
{
  "status": "success",
  "synced_count": 1
}
```

## Part 3: Search / Vector API (Protected)
Since we are generating embeddings on the backend, you'll need an endpoint to actually search through them based on semantic similarity.

### 3.1 Semantic Search
Search for thoughts using natural language.

**Request:** `POST /thoughts/search`
**Body:**
```json
{
  "query": "ideas about marketing",
  "limit": 10
}
```

**Response: `200 OK`**
```json
[
  {
    "id": "uuid-string",
    "content": "We should do more content marketing on Twitter",
    "similarity": 0.89,
    "captured_at": "2024-01-03T14:20:00Z"
  }
]
```

## Part 4: Mind-map / RAG (Protected)

### 4.1 Thought graph
Nodes are the user's live thoughts; edges link embedding-similar ideas.

**Request:** `GET /thoughts/graph`
**Headers:** `Authorization: Bearer <token>`

**Response: `200 OK`**
```json
{
  "nodes": [
    {
      "id": "uuid-string",
      "content": "Ship a weekly idea newsletter",
      "insight": "A newsletter only works if the cadence is survivable.",
      "captured_at": "2024-01-03T14:20:00Z"
    }
  ],
  "edges": [
    {
      "source": "uuid-string",
      "target": "uuid-string-2",
      "similarity": 0.81
    }
  ]
}
```

### 4.2 Chat over the graph
Retrieve similar thoughts, expand via graph neighbors, and answer with citations.

**Request:** `POST /thoughts/chat`
**Body:**
```json
{
  "message": "What have I been thinking about marketing?",
  "history": [
    {"role": "user", "content": "any notes on writing?"},
    {"role": "assistant", "content": "You mentioned a weekly newsletter."}
  ]
}
```

**Response: `200 OK`**
```json
{
  "answer": "You've been circling content marketing — especially a weekly newsletter and Twitter.",
  "sources": [
    {
      "id": "uuid-string",
      "content": "Ship a weekly idea newsletter",
      "similarity": 0.84
    }
  ]
}
```
